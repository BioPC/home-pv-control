1. RAW HBC DERIVATION
The native pure evaluator now accepts immutable raw Home Assistant states, timestamps,
heartbeat attributes and options. It derives availability, HPVC permission, Charge /
Charge PV execution state, count 0..6, count+1 rotation, SOC, power, observed maximum,
cutoffs, RS485 mode, freshness, eligible batteries and aggregate headroom. Missing and
numeric zero remain distinct. Malformed present configuration is restrictive.
Health preserves active/idle freshness corroboration, full-cutoff idle handling,
maximum-memory expiry and the 60-second continuously healthy recovery interval.

2. CHARGE PRIORITY
Off, Requested/Waiting diagnostics, Active and Exit hold are derived with the source
50 W entry and 25 W remain thresholds. Response and transition settle are 15 seconds,
persistent-export fallback is 30 seconds and exit hold is 20 seconds. Runtime elapsed
windows use monotonic time and do not infer continuous observation through restart.

3. BELOW 90 PERCENT
Initial bounded PV release is allowed before measured battery charging. Aggregate
eligible headroom, current grid/export interaction, source large-step shaping and
reversal shaping are preserved. The evaluator does not exceed eligible headroom.

4. TAPER AND LEARNING
The 90-92, 92-94, 94-96, 96-98 and 98-100 SOC bands retain source scaling, per-battery
allowances, learned ceilings, 30-minute maximum memory and independent 48-hour band
expiry. Probe allowance is never promoted to learned capacity without evidence.
Confirmed learning requires each battery's independent fresh post-write sample.
Probe delay/timeout, partial response, contamination, failure/contamination counters,
lockouts, idle startup probes and repeated-failure recovery remain typed memory.
Aggregate taper release caps remain 10%, 6% from 95% SOC and 3% from 98% SOC.

5. IMMUTABLE MEMORY
Frozen typed records represent observations, clocks, maximum memories, per-band
profiles, samples, pending probes, results, contamination, lockouts and expiry.
Pure evaluation returns proposed next memory and never writes storage or creates tasks.

6. NEGATIVE-PRICE OVERRIDE
Original strategy and charge goal are captured under a durable token before a forced
select intent becomes eligible. Entry orders strategy then goal; exit orders goal then
strategy and requires independent raw confirmation. Unavailable/unknown originals,
permission changes, retries, stuck phases, fault publication and recovery remain
conservative. Ordered action intents are DATA only. Accepted simulated events own
issued flags, retry clocks and fault-publication facts; policy cannot manufacture them.
Fault-notification acceptance cannot delay the select retry clock.

7. CALLER-SIDE RUNTIME ADAPTER
The read-only coordinator now evaluates raw HBC and pure policy with its own memory
adapter. Proposal, accepted runtime memory, durable memory and execution-owned facts
are separate. Two private schema-1 companion stores are added: policy_memory and
accepted_commands. Generation, ledger revision and fact revision reject stale proposals.
Corrupt/missing companion stores and failed commits fail closed. Loading resets partial
observation windows while preserving active Night Restore and durable override originals.

8. COOLDOWN OWNERSHIP
Only simulated execution-owned accepted/issued events start cooldown. The recorder
requires an in-flight durable operation, the latest accepted policy evaluation,
represented target, observed before-value, configuration/controller/dispatch/owner
provenance and clock continuity. HBC events additionally match the native payload and
capture token. Pure planning/persistence, fake service completion and cache state cannot
create acceptance. Restart honors the original accepted UTC deadline without starting
a fresh interval; backward-wall-clock uncertainty remains restrictive.

9. AUTHORITATIVE EXECUTION SNAPSHOT
The immutable snapshot comes from the durable ledger and accepted-command facts.
Unresolved physical operations, pending verification, settling restrictions, restore
obligations, maintenance, ownership uncertainty, replaced/removed controller identities,
failed/unknown outcomes and per-controller eligibility are represented. Helper/cache
state cannot resolve durable uncertainty. Logical planning eligibility never changes
the literal-false physical authorization property.

LIMITS
This completes the approved derivation/adapter stage. It does not validate hardware
response, live dispatcher behavior, legacy quiescence or production readiness. Atomic
file replacement/checksums do not claim universal power-loss durability. Dispatcher
