# HPVC 2.0.0-dev.2 read-only architecture

This stage implements phases B–E after the real HA acceptance checkpoint in phase-a-accepted.md. Native physical write authorization is unconditionally false. Command plans are immutable data and have no execution interface.

## Adapters and fleet

Generic Number normalizes missing, unknown, unavailable, stale and numeric observations, validates configured/native ranges, preserves manual Full Limit, and represents Watt/Percent steps and hard minimum/import floors. The frozen fixture tests/fixtures/readonly-v1.6-oracle.json contains 528 results generated by executing the original v1.6 flow's quantizeWattsTarget and quantizePercentTarget functions in Node; Python must match every result.

Generic Action preserves action identification, fixed/target JSON, nested dot fields, recursive typed/exact and embedded-string tokens, unknown token preservation, pre/main/post ordering, Watt/Percent action steps, initial-sync/refresh reasons, optional independent readback and explicit open-loop command-cache/startup assumptions. No service is called.

Detection prefers entity/device registry metadata, recognizes renamed Enphase DPEL triplets, validates Production/Export capability and rejects disabled/ambiguous/wrong-role controls. OpenDTU detection accepts MQTT non-persistent absolute-Watt controls; persistent/relative controls are not auto-discovered. Conservative suffix fallback is limited to unavailable registry metadata. Explicit user-selected generic controls retain the generic contract.

OpenDTU full power uses API > identity-bound API cache > manual Full Limit > unknown. HA number maximum is never a rated-power source. API cache lives only within the config-entry runtime; after restart fresh API evidence or the manual fallback is required. Enphase power ranges remain user-owned and are bound against replacement identities.

One InverterManager snapshot distinguishes configured, effective, participating, available, writable-capable and independently-verifiable controllers. Capability never grants authorization. There are at most ten effective controllers; overflow is reported. Deduplication, registry identity, identity-bound auto opt-out, replacement, removal/reappearance and rebalance intent are represented without allocation or writes. Manual entity-ID rename resolution is entry-runtime registry alias tracking; a stale manual entity reference after restart needs an explicit configuration update. Metadata-discovered renamed Enphase entities are reconciled from the registry on every discovery refresh.

## Verification, recovery and settling

Verification requires operation/controller/configuration/owner epoch/dispatch identities, fresh independent observations and target agreement. OpenDTU evidence requires a post-dispatch poll, receive-after-poll ordering, <=120-second age, established device/serial matching, positive rating, credible relative limit and Ok status. HA readback requires post-dispatch reported time and <=180-second age. Enphase additionally requires fresh observed enable and Production readiness. Command cache, startup assumptions, elapsed time and legacy helpers cannot prove success.

Diagnostic evidence verdicts do not automatically resolve ledger operations, release unknown execution occupancy, authorize restoration or mutate ownership. Restart first durably reconciles armed/in-flight records to unknown and reconstructs missing restore obligations under original operation/controller/configuration identities. Missing archived full-power data remains an explicitly unknown required target; a replacement in the same slot cannot satisfy old work.

Settling is pure observation logic: directional PV response or source-equivalent no-response-needed conditions, distinct fresh samples, two stable samples for large changes, and bounded timeout fallback. A timeout never establishes physical restoration.

This stage deliberately does not implement the v1.6 pre-write-already-full shortcut as restoration authority. Verification conservatively requires post-dispatch evidence. The shortcut belongs to the later separately tested operation/maintenance lifecycle.

## Entities and scheduling

The native entity surface totals 282 intended IDs: the dev.1 178 plus 104 additions. Added sensors expose effective runtime, range validation, entity display, discovery registry, ten actual/readback Watt limits and ten auto identities. Added binary sensors expose seven per-controller diagnostics and slot visibility for slots 2–10. number.hpvc_inverters is a validated configuration facade with an auto-discovery floor; setting it cannot call an inverter. Approved public object names are retained, subject to existing HA registry ownership/collisions.

Registry discovery runs at 2 seconds then every 60 seconds; OpenDTU GET status at 8 seconds then every 30 seconds. The coordinator owns and drains both workers on unload/reload. Source events mark telemetry dirty, preserving the foundation evaluation cadence. Read-only HTTP failures are bounded and exposed as readonly_worker_faults.

## Real HA compatibility

Phase A passed on HA 2025.12.0 and 2026.10.4 before expansion. The expansion's first minimum-version run found an actual Number API compatibility defect: older HA reads value while newer HA reads native_value. The inverters facade now explicitly implements both. The minimum test environment pins pycares 4.11.0 because aiodns 3.5.0 bundled with that historical HA/test dependency set is incompatible with pycares 5.x. No HA version or product behavior was weakened.

See the delivered validation JSON and completion report for exact final run IDs/results. Tests trap HA service calls during setup, setters, read-only refresh/poll, reload, recovery and unload; AST checks reject actuator service helpers, MQTT/raw transports, adapter execution and any HTTP session method other than the single status GET.

## Remaining scope

No service dispatcher, physical inverter/HBC writes, final engine, allocation execution, Node-RED fencing, ownership cutover, merge, release or deployment is included. The recommended next stage is pure policy/allocation with simulated end-to-end operation and recovery tests, still with physical writes hard Off.
