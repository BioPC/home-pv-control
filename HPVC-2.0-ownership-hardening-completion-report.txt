3. EXACT NEW OWNERSHIP DECISION RULE

Both proof paths require ALL of:
- approved catalogue membership for the exact domain/platform/unique-ID triple;
- absent config-entry ownership;
- no duplicate registry identity;
- no contradictory supplied package hash, match flag or package reference;
- no manifest row contradicting the current entity's actual registry tuple.

The catalogue describes YAML-owned templates. No config-entry ID is the valid
legacy ownership fact (None or empty string in an export). A supplied nonempty ID
is checked against the local config_entries evidence: absent/ambiguous entries
are unresolved; uniquely resolved entries are conflicting owners for these YAML
identities. Neither condition may be converted to proof by an operator assertion.

Only proven_legacy_hpvc_owned may reach the existing preview proposal builder.
unproven_collision and unrelated remain distinct. No proposal is executed.

4. HOW THE MANIFEST NOW INTERACTS WITH THE CATALOGUE

The explicit channel remains supported. An exact valid manifest records
proof=exact_supplied_registry_manifest, supplements approved catalogue evidence,
and supports renamed entities through their stable approved unique IDs.
Without a manifest, valid exact catalogue identities can still be recognized.

The manifest is never an alternative to mandatory checks. Contradictory rows for
the same current entity veto proof even if another manifest row matches. Claims
about another entity do not supply proof for the current one. Names alone grant
nothing. Package contradictions and duplicate registry identities veto both paths.
